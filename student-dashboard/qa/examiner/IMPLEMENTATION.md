15. **Profile to Security:** PASS. Valid profile save updates header identity and selects Security. Invalid email and unsupported/oversized image files are rejected. Image selection remains local to the browser.
16. **Account Saved:** PASS. Valid Security save opens the custom success popup and clears password inputs. Raw passwords are never passed to the persisted context or stored in localStorage. This is a frontend simulation, not an authentication service.
17. **Bell:** PASS from all tested shared-header routes. Opens Notifications. Notifications support opening assigned sessions and marking updates read.
18. **Clock:** PASS. Opens a shared recent-tasks dropdown; second click, outside click and Escape close it. Activity is generated by examiner actions. Dialogs use a document-level portal, trap keyboard focus, restore focus and lock background scrolling.
19. **SRS requirements:** Read the supplied `references/Music Exam System SRS.pdf`, including evaluator role permissions and FR-018/FR-019. Implemented assigned-instance marks, derived grade/Pass-Fail, draft saving and administrator review submission. Reused existing grade thresholds: Distinction >=90, Merit >=75, Pass >=60; the applicant helper's below-60 `Review` classification is represented as `Fail` in the examiner workflow. Marks are finite numbers in 0-100, with up to two decimal places.
20. **Assigned-instance restriction:** PASS in route and reducer checks. Unknown or unassigned session IDs cannot be opened or modified. Search is limited to the examiner's assigned state. These are frontend boundaries; production authorization still requires a backend. Examiner submission does not modify student results or publish records.
